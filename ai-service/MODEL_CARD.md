# Model card: TruthGuard classifier

## Overview

| Field | Value |
| --- | --- |
| Task | Three-way text classification: `real`, `fake`, `propaganda` |
| Architecture | Fine-tuned encoder (`distilbert-base-uncased` or MiniLM) + linear head |
| Runtime form | int8 dynamically quantized ONNX, CPU inference |
| Input | English text, up to 20,000 characters (tokenized/truncated at 256 tokens) |
| Output | Calibrated class probabilities; abstains as `uncertain` below the manifest threshold |
| Versioning | Semver-like version string embedded in `manifest.json` and returned per analysis |
| Generative AI | None. No text is generated by a model, and no third-party AI API is called |

The classifier is one part of an analysis response. The API also returns
deterministic signals — lexicon hits, bias score, emotion hint, and important
tokens found by occlusion — which are rule-based and do not depend on the
model. The explanation text is assembled by templates.

## Intended use

- Flagging news-like English text that shows patterns associated with
  misinformation or propaganda, as a **screening aid**.
- Helping readers pause and check primary sources before sharing.
- Research, classroom, and newsroom triage where a human reviews results.

## Out of scope

- Fact-checking. The model judges textual patterns, not whether a claim is
  true; it cannot verify events, numbers, quotes, or sources.
- Deciding whether a person, outlet, or organization is trustworthy.
- Non-English text (the service rejects it), satire/parody as a separate
  category, images, video, audio, or social-graph context.
- High-stakes decisions (legal, medical, immigration, moderation bans) without
  independent human review.
- Adversarial or deliberately paraphrased disinformation written to evade
  lexical patterns.

## Training data

The pipeline consumes public misinformation datasets; the exact mixture is
recorded in `training/data/processed/dataset_stats.json` for each trained
version.

| Dataset | Role | Notes |
| --- | --- | --- |
| LIAR | political statement veracity | `half-true`/`barely-true` excluded as ambiguous |
| ISOT | news article authenticity | publisher-hosted |
| WELFake | news article authenticity | label polarity is configurable |
| Propaganda / FakeNews | propaganda style | optional |

Datasets are not redistributed with this repository. Licences and any
redistribution constraints must be reviewed before publishing weights; a model
trained on a dataset may inherit restrictions on commercial use. Confirm terms
with each publisher before a production release.

## Evaluation

Metrics are produced by `training/evaluate.py` against the held-out test split
and written to `artifacts/evaluation.json`. That file, together with
`manifest.json`, must be published alongside every released artifact. The
deployment gate (default macro F1 ≥ 0.70, fake recall ≥ 0.70) is enforced twice:
during training and during artifact evaluation.

**This repository does not contain a trained artifact.** Until an operator runs
the pipeline and configures `MODEL_ARTIFACT_URL` / `MODEL_ARTIFACT_SHA256`, the
service runs in explicit heuristic mode in development and refuses to start in
production. Do not quote metrics for a model that has not been trained and
evaluated.

Reported metrics should include, at minimum:

- accuracy and macro F1 overall
- coverage at the uncertainty threshold, and accuracy on covered samples
- per-class precision/recall/F1 and support
- fake-class recall (the costly error direction)

## Limitations and risks

- **Dataset bias.** Labels reflect the source datasets' editorial choices.
  Political text and outlet style can correlate with labels, so the model can
  learn source cues rather than misinformation cues. Cross-dataset performance
  is typically lower than in-distribution performance.
- **Temporal drift.** Vocabulary and topics shift; a model trained on older
  articles degrades on current events. Re-evaluate on recent, hand-labelled
  samples before each major release.
- **Domain shift.** The training mix is mostly US political news. Performance
  on science, health, local news, or non-US outlets is unverified.
- **Short text.** Statements under a few dozen tokens give the encoder little
  evidence; confidence may be poorly calibrated in that regime.
- **Quantization.** int8 dynamic quantization trades a small amount of accuracy
  for size and speed. Always evaluate the quantized artifact, not just the
  PyTorch checkpoint.
- **Adversarial evasion.** Keyword-level edits can flip predictions. Never treat
  a `real` verdict as proof of authenticity.
- **Feedback loop.** User feedback is stored for review but is not used for
  automatic retraining, so it cannot silently reinforce biases.

## Ethical considerations

Outputs are probabilistic and can be wrong. The UI labels the classifier mode
and marks low-confidence results as `uncertain`. Heuristic mode is explicitly
labelled as not a model prediction and is blocked in production by default.
Users can delete analyses and export their data. Analyses contain user-submitted
text, so retention is bounded by `ANALYSIS_RETENTION_DAYS` and access is scoped
to the owning account (admins see aggregates and feedback, not analysis text).
